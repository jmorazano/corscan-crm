# API pública v1 — envíos programáticos por empresa

Superficie HTTP para que el sistema de una empresa (reservas, turnos,
pedidos…) envíe notificaciones de WhatsApp a sus clientes a través del CRM,
con las plantillas aprobadas de esa empresa. Cada mensaje queda en la
bandeja como cualquier otro; las respuestas las atiende el equipo o el
agente de IA.

- **Base URL**: la de la instancia (p. ej. `https://crm.tu-dominio.com`).
- **Autenticación**: `Authorization: Bearer vk_…`. Las claves se crean en
  **Ajustes → API** (solo el propietario); se muestran una sola vez.
- **Formato**: JSON. Errores: `{ "error": { "code", "message", … } }`.
- **Límite**: 60 llamadas por minuto por clave (`429 rate_limited`).

## Flujo recomendado

1. Crear en el CRM una plantilla por evento (reserva confirmada,
   recordatorio de check-in, instrucciones de llegada, checkout, pedido de
   reseña), categoría **UTILITY**, eligiendo el origen de cada variable
   (nombre del contacto / empresa = las completa el CRM; texto libre = la
   manda tu sistema). Esperar la aprobación de Meta.
2. `GET /api/v1/templates` para leer nombres y variables.
3. `POST /api/v1/messages` por cada evento, con un `Idempotency-Key`
   propio del evento.
4. Opcional: `GET /api/v1/messages/{id}` para conocer la entrega.

## `GET /api/v1/templates`

Query opcional `status=all` para incluir pendientes/rechazadas (solo
diagnóstico: únicamente las `approved` se pueden enviar).

```json
{
  "templates": [{
    "id": "tpl_…",
    "name": "recordatorio_checkin",
    "language": "es",
    "category": "UTILITY",
    "status": "approved",
    "body": "Hola {{1}}, te esperamos en {{2}} el {{3}}.",
    "header_image": false,
    "variables": [
      { "index": 1, "origin": "contact_name", "provided_by": "crm", "label": "Nombre del contacto", "sample": "María" },
      { "index": 2, "origin": "free_text", "provided_by": "caller", "label": "Texto libre al enviar", "sample": "una promo especial" },
      { "index": 3, "origin": "free_text", "provided_by": "caller", "label": "Texto libre al enviar", "sample": "una promo especial" }
    ],
    "example": { "to": "+54 9 351 123 4567", "name": "Nombre del cliente", "template": "recordatorio_checkin", "language": "es", "params": { "2": "…", "3": "…" } }
  }]
}
```

`provided_by`:

- `crm`: el CRM la completa (nombre del contacto, nombre de la empresa).
  No la mandes.
- `caller`: la mandás vos en `params` con ese índice.

## `POST /api/v1/messages`

Headers: `Content-Type: application/json`, `Idempotency-Key` (opcional,
≤ 200 caracteres, **recomendado**).

```bash
curl -X POST https://crm.tu-dominio.com/api/v1/messages \
  -H "Authorization: Bearer vk_…" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: reserva-8812:recordatorio_checkin" \
  -d '{
    "to": "+54 9 351 688 2234",
    "name": "Juan Pérez",
    "template": "recordatorio_checkin",
    "params": { "2": "Cabaña Los Pinos", "3": "viernes 25/10 a las 14:00" }
  }'
```

| Campo | Obligatorio | Notas |
|---|---|---|
| `to` | sí | Teléfono con código de país (se normaliza; Argentina: se agrega el 9 de móvil si falta). |
| `name` | no | Se usa solo si el contacto es nuevo o no tenía nombre; no pisa lo que editó el equipo. |
| `template` | sí | Nombre exacto de la plantilla. |
| `language` | no | Obligatorio solo si el nombre existe en varios idiomas. |
| `params` | según plantilla | Objeto índice → valor, exactamente los índices `provided_by: caller`. 1–500 caracteres, sin saltos de línea, tabulaciones ni más de 4 espacios seguidos. |

Respuesta `201`:

```json
{
  "message": { "id": "msg_…", "status": "pending", "template": "recordatorio_checkin" },
  "contact": { "id": "ct_…", "phone": "5493516882234", "created": true },
  "conversation": { "id": "cv_…", "url": "https://crm.tu-dominio.com/inbox?c=cv_…" }
}
```

`pending` = aceptado por WhatsApp. La entrega (`sent`, `delivered`, `read`
o `failed`) llega después; consultala con el endpoint de estado o mirá la
bandeja.

### Idempotencia

Con `Idempotency-Key`, un reintento del mismo request (misma clave, mismo
cuerpo) devuelve la **misma respuesta** con el header
`Idempotent-Replayed: true` y **no envía de nuevo**. La misma clave con
otro cuerpo responde `422 idempotency_mismatch`. Si el request original
falló (4xx/5xx), la clave queda libre para reintentar. Usá una clave por
evento, por ejemplo `<id de reserva>:<evento>`.

### Qué hace el CRM al enviar

- Normaliza el teléfono al formato de WhatsApp.
- Crea el contacto (con consentimiento declarado por tu sistema) y la
  conversación si no existen; si existen, los reutiliza.
- Respeta la **baja** (`409 opted_out`) y el **cupo** de contactos
  iniciados por 24 h (`429 quota_exceeded` con `retryInSeconds`).
- Marca el mensaje como «Enviado por API · <nombre de la clave>» en la
  bandeja.
- Si el cliente contesta solo «gracias»/«ok», el agente de IA no responde;
  si pregunta o pide algo, lo atiende.

### Errores

| HTTP | `code` | Cuándo |
|---|---|---|
| 401 | `invalid_api_key` | clave ausente, inválida o revocada |
| 422 | `invalid_body` | JSON inválido o campos con formato incorrecto |
| 422 | `invalid_phone` | teléfono no normalizable |
| 404 | `template_not_found` | no existe la plantilla (con ese idioma) |
| 422 | `language_required` | el nombre existe en varios idiomas (`languages`) |
| 422 | `template_not_approved` | Meta no la aprobó (`status`) |
| 422 | `missing_params` | faltan índices (`missing`) |
| 422 | `unknown_params` | índices que el CRM completa o inexistentes (`unknown`) |
| 422 | `invalid_param` | valor vacío/largo/con saltos (`index`) |
| 422 | `template_not_supported` | plantilla anterior con varias variables sin orígenes: recrearla |
| 422 | `idempotency_mismatch` | misma `Idempotency-Key`, cuerpo distinto |
| 409 | `idempotency_in_progress` | misma `Idempotency-Key` en curso: reintentar en segundos |
| 409 | `opted_out` | el contacto pidió la baja |
| 409 | `sandbox_contact` | el teléfono es de un contacto de prueba del Laboratorio |
| 409 | `not_connected` / `reconnect_required` | el número de WhatsApp de la empresa no está operativo |
| 429 | `quota_exceeded` | cupo 24 h agotado (`retryInSeconds`) |
| 429 | `rate_limited` | más de 60 llamadas/min con la clave |
| 422 | `meta_error` | WhatsApp rechazó el envío (mensaje de Meta) |
| 503 | `meta_unavailable` | WhatsApp no disponible: reintentar con la misma `Idempotency-Key` |

## `GET /api/v1/messages/{id}`

```json
{
  "message": {
    "id": "msg_…",
    "status": "delivered",
    "error": null,
    "error_raw": null,
    "template": "recordatorio_checkin",
    "to": "5493516882234",
    "conversation_id": "cv_…",
    "created_at": "2026-09-18T12:00:00.000Z"
  }
}
```

`error` es una explicación en lenguaje claro cuando `status = failed`;
`error_raw` es el texto original de Meta. `404 not_found` si el id no
existe o no pertenece a la empresa de la clave.

## Fuera de v1

Webhooks hacia tu sistema (estados y respuestas), envío de texto libre
dentro de la ventana de 24 h, alta de plantillas por API.
